\begin{abstract}
Security fine-tuning makes LLMs better at classifying malicious code on canonical inputs — and simultaneously introduces evasion brittleness that standard accuracy evaluation cannot detect. We demonstrate this concretely for PowerShell classification in Foundation-Sec-8B-Instruct. Fine-tuning on a cybersecurity corpus caused the model to learn strong associations between specific full-form command names (\texttt{Invoke-WebRequest}, \texttt{Invoke-Expression}) and malicious classification. This improves accuracy on canonical inputs, but creates an attack surface invisible to held-out test sets: replacing \texttt{Invoke-WebRequest} with its alias \texttt{iwr} — a trivial one-token substitution that preserves all malicious behavior — consistently flips the model’s prediction. The base model it was fine-tuned from, Llama-3.1-8B-Instruct, has zero misses on the same substitutions. The fine-tuning that was supposed to improve security classification created new vulnerabilities that did not exist before.

We show this brittleness is both predictable and detectable before deployment. Using causal interventions on a 293-pair matched cohort, we localize the classification circuit to a small set of late attention heads (Layer 12), and show this circuit is inherited from Llama rather than created by fine-tuning. A linear probe fit from base-model activations at the circuit boundary (\texttt{resid\_pre13}) to individual head contributions achieves \(r = 0.81\)--\(0.87\), confirming each head’s contribution is linearly encoded. An indicator-token ablation experiment then reveals the mechanism of brittleness: in Foundation-Sec, ablating the \texttt{Invoke-WebRequest} command-name tokens \emph{increases} malicious confidence (\(+1.13\) mean delta, positive in 73.7\% of scripts), while the same ablation \emph{reduces} Llama’s confidence (\(-1.60\)). This sign inversion — command name acting as suppressor rather than driver — is the direct mechanistic precursor to aliasing brittleness, and it is detectable on canonical clean inputs without generating any evasion variants. Prompt-level mitigations compound the problem: telling Foundation-Sec to ``classify based on overall purpose, not individual constructs’’ fixes the \texttt{Invoke-WebRequest} misses but simultaneously creates new misses on \texttt{Invoke-Expression} obfuscation. The semantic weighting introduced by fine-tuning is distributed across families in ways that interact non-trivially.

These results carry a direct operational implication for teams fine-tuning LLMs for security tasks: high accuracy on canonical test data does not imply robustness to aliasing attacks, and the brittleness is predictable from the fine-tuning data distribution. Any model trained on a corpus where specific command names are correlated with maliciousness is at risk of the same failure mode.
\end{abstract}

\textbf{Keywords:} security fine-tuning, aliasing brittleness, evasion robustness, large language models, malware detection, PowerShell, causal intervention

\section{Introduction}
LLMs are increasingly deployed in security workflows — code triage, malware analysis, policy-based blocking — because they achieve strong accuracy on standard benchmarks. But high accuracy on canonical test data does not mean a model is robust to the kinds of input modifications that adversaries routinely apply. This paper investigates a specific and practically important failure mode: \emph{aliasing brittleness} introduced by security fine-tuning. A model fine-tuned to classify malicious PowerShell learns associations between specific command names and maliciousness. Those associations improve accuracy on canonical inputs, but they also create a class of attack — token substitution via aliases or runtime reconstruction — that did not exist against the base model and is invisible to standard held-out evaluation.

The core finding is empirical and direct. Foundation-Sec-8B-Instruct, a cybersecurity fine-tune of Llama-3.1-8B-Instruct, achieves higher classification accuracy than its base model on canonical malicious PowerShell scripts. But Foundation-Sec fails on simple alias substitutions — replacing \texttt{Invoke-WebRequest} with \texttt{iwr}, or reconstructing \texttt{Invoke-Expression} via a format string — that preserve all malicious behavior. Llama, with no security fine-tuning, has \emph{zero misses} on the same substitutions under the same prompt framing. The fine-tuning created the brittleness.

This brittleness is not a random quirk. It follows directly from how fine-tuning changes the model's internal behavior. We show that Foundation-Sec learned to classify \texttt{Invoke-WebRequest} scripts primarily through URL patterns and payload context, with the full command-name token acting as a mild suppressor rather than a driver of malicious classification. When the alias \texttt{iwr} replaces the full name, the suppressor disappears alongside the payload-context attention it anchored, and the prediction flips. This mechanism is detectable before deployment — on canonical clean inputs, no evasion variants required — using a simple indicator-token ablation test at the model's internal classification boundary.

We also show that prompt-level mitigations compound the problem in ways that are difficult to anticipate. Adding a prompt instruction to ``classify based on overall purpose, not individual constructs'' fixes the \texttt{Invoke-WebRequest} misses, but simultaneously opens new misses on \texttt{Invoke-Expression} obfuscation: the semantic weighting fine-tuning added is distributed across families and cannot be patched in one place without opening another. This makes the pre-deployment detection workflow more valuable than post-deployment prompt engineering.

The mechanistic analysis supporting these findings uses causal interventions on a 293-pair matched cohort — paired benign and malicious scripts sharing the same suspicious indicator strings, so that classification differences cannot be attributed to trivial surface features. We localize the classification decision to a small set of late-stage attention heads (Layer 12), show this circuit is inherited from Llama rather than created by fine-tuning, and use a linear probe and indicator-token ablation to establish both that the circuit information is linearly encoded at the classification boundary and that the sign of each family's token dependency directly predicts aliasing vulnerability.

The contributions of this paper are:
\begin{itemize}[leftmargin=1.5em,itemsep=0.15em,topsep=0.15em,parsep=0pt,partopsep=0pt]
  \item A demonstration that security fine-tuning introduces aliasing brittleness invisible to standard accuracy evaluation, with Foundation-Sec producing misses on simple token substitutions that Llama handles correctly.
  \item A two-tier syntax-preserving evasion benchmark constructed from matched seed/variant pairs, enabling mechanistic attribution of classifier failures to specific token transformations.
  \item Evidence that the brittleness mechanism is a sign inversion: fine-tuning caused specific command-name tokens to suppress rather than drive malicious classification, making their aliases evasion vectors.
  \item A pre-deployment detection recipe: a linear probe at the model's classification boundary identifies which capability families have undergone sign inversion, without requiring evasion variant generation in advance.
  \item The finding that prompt-level mitigations for one brittle family can simultaneously open new brittleness in others, motivating data-level rather than prompt-level fixes.
\end{itemize}

\section{Prior Work}
Previous work on mechanistic interpretability provides the main template for this study. Early circuit work argued that neural networks can often be understood in terms of reusable features and the pathways that connect them \citep{cammarata2020thread}. Transformer-specific follow-up then formalized residual-stream communication and path-based decomposition \citep{elhage2021mathematical}, identified induction heads as a concrete algorithmic circuit for the completion of the in-context pattern \citep{olsson2022induction}, and showed that medium-scale language behavior can be partially decomposed into head-level circuits under causal intervention \citep{wang2023interpretability}. More recent work has also pushed toward more automated circuit discovery, which is directly relevant to the discovery-versus-validation split used here \citep{conmy2023automated}.

The model lineage matters for interpretation. Foundation-Sec-8B was introduced as a cybersecurity-focused derivative of the Llama 3.1 8B base architecture, obtained through continued pretraining on a curated cybersecurity corpus rather than training from scratch \citep{kassianik2025foundationsecbase}. Foundation-Sec-8B-Instruct then extends that base model with instruction tuning and human-preference alignment for chat-style cybersecurity use \citep{weerawardhena2025foundationsecinstruct}. This choice is relevant because the model was previously evaluated to perform favorably in PowerShell classification, with a reported \(+16\%\) precision gain over the baseline in a threat-hunting workflow  \citep{fetterman2025foundationsecpowershell}. It also creates a natural mechanistic control: if Foundation-Sec and Llama share the same circuit skeleton, then the cybersecurity fine-tuning should be interpreted as amplifying, reweighting, or adding semantic use of an inherited circuit rather than inventing a new one. Recent circuit analyses of fine-tuning similarly find that circuit nodes can remain highly similar before and after fine-tuning while the edge structure and functional weighting change \citep{wang2025finetuningcircuits}.

Adjacent robustness and security research motivate the evasion side of the paper. In malware detection and related security pipelines, detectors that perform well on nominal data can still fail under functionality-preserving adversarial modifications, and improving robustness often requires explicitly modeling the attack surface rather than assuming that high baseline accuracy implies stability \citep{lucas2023adversarial,mukherjee2023evading}. Our setting differs in that the detector is an LLM operating over PowerShell scripts, and the goal is mechanistic rather than purely behavioral. But the central concern is the same: if the model relies on brittle surface indicators, then conservative rewrites may change the decision without removing the underlying malicious behavior.

\section{Background}
This paper uses standard transformer notation. A label such as \texttt{L12H15} means \emph{Layer 12, Attention Head 15}. Attention heads read information from earlier tokens and write their output into a shared running state often called the \emph{residual stream}. When we say a head or layer ``carries malicious evidence,'' we mean that its contribution to this shared state pushes the model toward a malicious rather than benign classification. The model also contains \emph{MLP} blocks, the feed-forward sublayers that sit alongside attention in each transformer layer. In this paper, \texttt{resid\_pre13} simply names the shared activation state immediately before Layer 13.

We use the term \emph{circuit} in a narrow sense: a small set of model components whose activations causally matter for the classification decision under study. A \emph{route} is one specific path through that circuit. A \emph{late-stage bundle} is the group of late heads that transports the strongest malicious-versus-benign evidence near the output. A label such as \texttt{L0H11 $\rightarrow$ L12H15/L12H5/L12H4} should therefore be read as a shorthand summary of the route, not as the claim that these are the only relevant components in the full model.

Our main intervention tools are also simple in intent. \emph{Grouped path patching} asks whether copying activations from a malicious example into a candidate route is enough to recreate the malicious classification signal; in other words, it is primarily a sufficiency test. \emph{Grouped head ablation} asks whether removing a candidate group weakens the decision signal; it is primarily a necessity test. When we say a route is \emph{validated}, we mean that it survives these causal intervention checks on the matched cohort. When we say \emph{signal inversion}, we mean that the model still forms malicious evidence internally, but later computation changes the sign or use of that evidence before the final readout. Figures \ref{fig:route-comparison} and \ref{fig:shared-skeleton-reweighted-heads} provide the most direct visual summaries of these components and how they differ across the two models.

\section{Problem Setting}
The task is binary malicious-code classification for PowerShell scripts. The key mechanistic difficulty is that many suspicious strings are not uniquely malicious: benign administrative scripts can contain tokens such as \texttt{IEX}, \texttt{FromBase64String}, \texttt{DownloadString}, \texttt{Invoke-WebRequest}, or \texttt{-EncodedCommand}. We therefore use matched benign and malicious examples sharing suspicious indicators, so that the interpretability problem is not trivially solved by superficial token presence alone.

\section{Dataset and Evaluation Cohorts}
\subsection{Source Dataset}
The source corpus contains 2{,}556 labeled PowerShell scripts, derived from prior work\citep{FANG202130}. The class balance after filtering is approximately even. A substantial long tail of long scripts motivated  a 12,000-character pre-processing cap when building the analysis manifests and construction of the matched cohorts, so benign and malicious scripts were paired and selected under explicit length control rather than letting the very longest scripts dominate the mechanistic runs. The main evidentiary basis for this draft is a 293-pair within-family matched cohort drawn from 456 unique scripts across the seven indicator families, in which benign and malicious scripts share suspicious indicators while remaining length-controlled enough for the intervention pipeline. This cohort was filtered from 380 candidate pairs by requiring both members of each pair to be correctly classified at baseline. 

\section{Methods}
\subsection{Discovery}
The goal of the discovery phase is to identify a small number of candidate components that repeatedly carry malicious-versus-benign evidence before we run the stronger causal tests in the validated route analysis below. Concretely, we first inspect \emph{attention recurrence}: whether the same early and late heads repeatedly attend to suspicious command spans, URLs, or execution sites across matched examples. We then use reduced-layer head interventions and coarse full-model layer ablation to ask a localization question: if a candidate head or layer band is removed, does the malicious judgment weaken enough to justify carrying that component forward into the validated route search? This is methodologically closest to earlier circuit-discovery work that treats attention patterns, residual-stream communication, and coarse intervention effects as a way to narrow the search space before making a sharper causal claim \citep{cammarata2020thread,elhage2021mathematical,conmy2023automated,ameisen2025attributiongraphs}.

Two discovery tools are especially important for the present paper. First, \emph{residual-direction patching} defines a task-aligned direction from matched benign-versus-malicious examples and then asks whether replacing activations at a given site moves the model along that malicious direction. Intuitively, this tests whether a location in the network is carrying classification-relevant evidence rather than only showing generic activation magnitude. Second, \emph{head-write tracing} breaks the contribution at that site into the individual head outputs that push in that direction, which lets us identify a small set of dominant heads instead of treating an entire layer as monolithic. These discovery analyses do not by themselves establish a validated circuit, but they are the reason the final claim can be stated narrowly as an \texttt{L0H11}-to-Layer-12 route rather than as a vague statement about ``early'' and ``late'' computation. This use of residual directions, head-level intervention, and candidate-route narrowing follows the general logic of recent transformer-circuit studies, especially work on induction-style circuits, IOI-style causal localization, and automated circuit search \citep{olsson2022induction,wang2023interpretability,conmy2023automated}.

\subsection{Validation}
The final claim is based on grouped interventions on the 293-pair cohort:
\begin{itemize}[leftmargin=1.5em,itemsep=0.2em,topsep=0pt,parsep=0pt,partopsep=0pt]
  \item \textbf{Grouped path patching} is used primarily as a sufficiency test.
  \item \textbf{Grouped head ablation} is used primarily as a necessity test.
\end{itemize}

In simple terms, a \emph{sufficiency} test asks whether a candidate route is enough to recreate the relevant behavior when its activations are patched in from a malicious example. A \emph{necessity} test asks whether the behavior weakens when that route is removed or disabled. These are related but not identical questions: a route can be sufficient without being strictly necessary if the model has backup pathways, and it can be necessary in a narrow setting without being the cleanest transportable route for patching.

Throughout the paper, \emph{mean intervention effect} refers to the average shift produced by an intervention on the model's malicious-versus-benign decision score. A more negative mean effect therefore indicates a stronger push toward the malicious judgment under the intervention. \emph{Flip rate} reports how often that intervention is strong enough to change the model's final predicted label. 

\subsection{Evasion}
We evaluate syntax-preserving obfuscation techniques and then, for the strongest misses, compare each original malicious script with its rewritten variant using the same circuit probes. Candidate variants are generated only from malicious seed scripts that the model initially classifies correctly, so the evasion benchmark measures failures relative to seeds that already pass the baseline classifier. Throughout this section, \texttt{evasion} means behavioral evasion of classification, that is, a malicious variant that the model now predicts benign. The central mechanistic question is whether successful evasion removes the validated malicious-evidence route or instead preserves that route while later computation changes how that evidence is used. In the best-localized current case, this change appears at the Layer 13 boundary: feed-forward computation before that boundary introduces a competing signal that reverses the effect of the surviving late-stage bundle.

The implemented benchmark is two-tiered. \texttt{direct\_v1} relies on alias substitution, call-operator indirection, token splitting, and literal or method-name reconstruction. \texttt{reconstructive\_v2} stresses the classifier with character-level and command-reconstruction patterns that are often seen in obfuscated PowerShell, including backticks, format strings, ASCII or Base64 recovery, invisible Unicode normalization, and alternate quoting or subexpressions. The benchmark schema defines five broad evasion families; this draft instantiates the \texttt{keyword\_hiding}, \texttt{string\_construction}, and \texttt{execution\_indirection} families.

The implemented benchmark pipeline is more specific than a generic ``obfuscation sweep.'' It first builds a malicious seed manifest restricted to baseline-correct malicious scripts. It then applies only a fixed set of allowed rewrites from the requested preset (\texttt{direct\_v1} or \texttt{reconstructive\_v2}), and each rewrite is used only on scripts where it makes sense. For example, a rewrite that hides \texttt{Invoke-WebRequest} is only applied to seeds that actually contain that command, and a rewrite intended for cross-runtime PowerShell is only used when the target script fits that runtime setting. Each generated variant is then reviewed with static parsing, using the PowerShell parser when the required runtime is available and a \texttt{tree-sitter} fallback otherwise, together with explicit invariant checks to ensure underlying behavior is not changed. The current invariant checks require preservation of URL sets, executable or path-like literals, and \texttt{-EncodedCommand} equivalence where relevant, and they also enforce technique-specific argument-preservation checks such as preserved request arguments or preserved process-launch arguments. The malicious seed / variant pairing is what makes the mechanistic experiments interpretable, we measure the same circuit on the same script content under two conditions (literal token present vs. absent) and attribute any difference in the residual stream directly to the token transformation.

\section{Evaluation \& Results}
\subsection{Results at a Glance}
\begin{itemize}[leftmargin=1.5em,itemsep=0.2em,topsep=0pt,parsep=0pt,partopsep=0pt]
  \item \textbf{Main validated route:} On the 293-pair cohort, the cleanest minimal direct branch is \texttt{L0H11 $\rightarrow$ L12H15/L12H5/L12H4}, supported by causal patching and grouped ablation.
  \item \textbf{Stronger late-stage bundle:} The broader late head bundle \texttt{L12H15/L12H5/L12H4/L12H28} is the strongest overall route in the main 293-pair comparison.
  \item \textbf{\texttt{L12H2} is auxiliary, not core:} Removing \texttt{H2} improves the main patching result, but including \texttt{H2} still helps grouped ablation for several families. This is why we treat it as an auxiliary helper rather than part of the stable sufficiency core.
  \item \textbf{Foundation-Sec inherits the circuit skeleton:} Llama-3.1-8B-Instruct shares the \texttt{L0H11} early detector and Layer-12 integration stage, but its best route is more diffuse and centered on \texttt{L12H28/L12H5/L12H4/L12H13}.
  \item \textbf{Family-level variation is real:} The best route is not identical across all indicator families. Some families prefer the minimal branch, some prefer the fuller top-five bundle, and several are strongest under the \texttt{H2}-free carrier.
  \item \textbf{Strongest current successful-evasion results:} Under both \texttt{invoke\_webrequest\_alias} and the new \texttt{invoke\_expression\_format\_string} slice, the late malicious-evidence bundle still appears earlier in the late stage; in the better-localized \texttt{Invoke-WebRequest} case, the failure is best described as later feed-forward computation reversing that evidence rather than deleting the route.
  \item \textbf{Broader evasion coverage:} Foundation-Sec has \(6/44\) misses on \texttt{direct\_v1} and \(4/46\) misses on \texttt{reconstructive\_v2}. In the controlled raw-prompt comparison, Llama has \(0/44\) misses on \texttt{direct\_v1} and \(0/46\) misses on \texttt{reconstructive\_v2}.
  \item \textbf{Bottom line:} The current evidence supports a mechanistic story in which fine-tuning preserves an inherited structural route but adds semantic weighting that can reverse the malicious-evidence signal before final readout.
\end{itemize}

\subsection{Circuit Results}
\subsubsection{Validated Late Route}
On the 293-pair cohort, causal patching supports a minimal direct branch:
\[
\texttt{L0H11} \rightarrow \texttt{L12H15/L12H5/L12H4}
\]
The mean patching effect is approximately \(-3.614\), which means that the intervention reduces the model's average malicious-versus-benign decision margin from about \(4.71\) to about \(1.10\). In other words, it removes roughly \(77\%\) of the average malicious decision margin and flips the final prediction on \(87/293\) pairs (\(0.297\)).

The stronger late-stage bundle is:
\[
\texttt{L12H15/L12H5/L12H4/L12H28}
\]
Its mean patching effect is approximately \(-3.824\), which reduces the same average malicious-versus-benign decision margin from about \(4.71\) to about \(0.89\). In other words, it removes roughly \(81\%\) of the average malicious decision margin and also flips the final prediction on \(87/293\) pairs (\(0.297\)).

The role of \texttt{L12H2} is more nuanced. Removing \texttt{H2} improves the main path-patching result, while the full top-five bundle remains slightly stronger under grouped ablation. Our current interpretation is therefore that \texttt{L12H2} is an auxiliary family-sensitive helper, not part of the most stable sufficiency core.

\subsubsection{Interpretation of Early and Late Stages}
The results support an early Layer 0 detector family, especially \texttt{L0H11} and \texttt{L0H9}. However, the final validated claim in this draft does not rest on a broad early-head story. Instead, it uses \texttt{L0H11} as the clearest entry point into the validated late route. The stronger late-stage evidence localizes to attention around Layers 12--13 and to feed-forward computation before the Layer 13 boundary that becomes especially important in the successful-evasion setting.

\subsubsection{Family-Level Variation}
The 293-pair cohort also reveals a useful family-level pattern. The best patch route is not identical across all indicator families. The minimal branch is strongest for \texttt{DownloadFile}, the fuller top-five late bundle is strongest for \texttt{DownloadString} and \texttt{IEX}, and the \texttt{H2}-free carrier (late Layer-12 head bundle with L12H2 removed) is strongest for \texttt{-EncodedCommand}, \texttt{Invoke-Expression}, and \texttt{Invoke-WebRequest}. This pattern supports the current interpretation that \texttt{H2} is not part of the most stable sufficiency core. One caveat: the \texttt{-EncodedCommand} family (7 pairs) shows zero flip rate under all patching variants, indicating that the circuit claim is weakest for this family and that it warrants a cautionary note; the other six families show consistent negative mean deltas across all route variants.

At the same time, grouped ablation suggests that \texttt{H2} still contributes a necessity signal across most families: the top-5 bundle (mean \(\Delta = -2.174\)) is stronger than the H2-free carrier (mean \(\Delta = -1.893\)), confirming \texttt{H2} as an auxiliary helper that matters for necessity even while it weakens patching sufficiency. The family-level picture therefore reinforces the write-up distinction between a stable late-stage bundle and a narrower auxiliary helper.

This comparison changes the interpretation of the Foundation-Sec results. The cleanest account is not that security training created the \texttt{L0H11}-to-Layer-12 circuit. Instead, fine-tuning appears to concentrate causal weight into a smaller late-head set and add semantic associations between full-form PowerShell command names and the final \texttt{BLOCK} decision. This is consistent with fine-tuning work showing node-level circuit persistence alongside edge and weighting changes \citep{wang2025finetuningcircuits}. On the matched 74-pair adversarial-prompt baseline, that semantic weighting corresponds to a \(4.7\)-percentage-point overall accuracy gain over Llama (\(100\%\) vs.\ \(95.3\%\)), driven entirely by a \(9.5\)-point benign-accuracy improvement (\(100\%\) vs.\ \(90.5\%\)) rather than by improved malicious recall. Notably, fine-tuning does not straightforwardly strengthen the circuit's causal margins: Llama's late carrier mean patching effect is \(-5.45\) versus Foundation-Sec's \(-3.82\) on a comparable route, and Llama's mean base logit diff for malicious examples is \(8.15\) versus Foundation-Sec's \(3.75\). This suggests that fine-tuning concentrates and semantically specialises the circuit without increasing its absolute signal strength, and indeed may attenuate the base model's stronger discriminative representation. The current evidence therefore supports a mechanistic story in which fine-tuning preserves an inherited structural route but adds semantic weighting that can invert the malicious-evidence signal before final readout. That semantic layer is useful for raw-prompt operation, but the evasion benchmark below shows that it also creates a specific attack surface around aliases and command reconstruction.

\subsection{Evasion Results}
Foundation-Sec's results separate cleanly by tier. Because the benchmark is conditioned on baseline-correct malicious seeds, these evasion failures should be read as misses on scripts the model initially handled correctly before rewriting. In \texttt{direct\_v1}, Foundation-Sec stays correct on \(38/44\) accepted variants and the misses are concentrated in two techniques rather than spread broadly across the conservative benchmark. The strongest direct-tier failure remains simple alias substitution in the \texttt{Invoke-WebRequest} family: replacing the full command name with \texttt{iwr} yields misses on all four tested variants. The only other positive result in that tier is narrower. Indirect \texttt{DownloadString} method invocation produces misses in two of six variants, and both of those misses come from \texttt{FromBase64String}-linked seeds rather than from the direct \texttt{DownloadString} seeds themselves.

Foundation-Sec classification accuracy is still strong under the second tier. In \texttt{reconstructive\_v2}, it stays correct on \(42/46\) candidates. All four misses come from one keyword-hiding technique, \texttt{invoke\_expression\_format\_string}. The other reconstructive rewrites---including backtick splitting, Base64 or ASCII reconstruction, subexpression strings, and zero-width normalization for \texttt{-EncodedCommand}---remain negative in the current run. Across both implemented tiers together, Foundation-Sec stays correct on \(80/90\) accepted variants, so the observed weaknesses are specific and technique-concentrated rather than benchmark-wide.

The \texttt{reconstructive\_v2} miss slice provides an independent replication of the same carrier-survival story, though not yet the same degree of localization for the competing write. On \texttt{invoke\_expression\_format\_string}, early-head ablation still flips \(4/4\) variants, the minimal direct patch route still flips \(4/4\) with mean effect about \(-0.875\), and the fuller late bundle still flips \(4/4\) with mean effect about \(-1.03\), even though removing that late bundle pushes the model in the opposite direction on the evaded variants. In the current interpretation, both slices are therefore better explained by preserved late-bundle activity plus an inversion-producing competing write than by simple route deletion. This framing is consistent with the broader lesson from recent mechanistic studies that behaviorally similar outputs can arise from materially different internal pathways and downstream uses of shared evidence \citep{lindsey2025biology}.

In Foundation-Sec \texttt{direct\_v1}, misses occur only in \texttt{invoke\_webrequest\_alias} and the narrower \texttt{downloadstring\_psobject\_invoke} pattern concentrated in \texttt{FromBase64String}-linked seeds. \subsection{Monitoring Fine-Tuning Drift}
The comparative and evasion results support a practical operational extension. Foundation-Sec inherits the underlying PowerShell classification route from Llama, but its failures after fine-tuning are not best explained as deletion of that inherited mechanism. Instead, the current evidence points to a narrower change in how later computation uses that inherited signal: the relevant malicious-evidence representation still appears at the causally important \texttt{resid\_pre13} site, while downstream computation can suppress, redirect, or invert its effect for particular semantic families. This makes activation-space monitoring a concrete regression tool for security fine-tunes rather than only a theoretical possibility.

\paragraph{Linear probe at the circuit boundary.}
We fit a linear probe (Ridge regression, 5-fold cross-validation) from the \texttt{resid\_pre13} activation of each malicious script to the per-head contribution of the four core Layer-12 heads measured by the head trace experiment. The probe achieves cross-validated \(r = 0.81\)–\(0.87\) for \texttt{L12H4}, \texttt{L12H5}, \texttt{L12H15}, and \texttt{L12H28} (\(n = 206\), all \(p < 10^{-45}\)). These values confirm that each head's contribution to the contrastive direction is \emph{linearly} encoded in \texttt{resid\_pre13} — a stronger claim than extractability by a flexible model, since it means the information is directly readable as a linear projection of the inherited representation. Applied cross-model, the same linear probe predicts Foundation-Sec's causal circuit dependence (\texttt{delta\_logit\_diff} under top-5 L12 ablation) at \(r = 0.41\) (\(n = 293\), \(p < 10^{-12}\)), establishing the cross-model transfer ceiling: roughly 40\% of per-script circuit importance in Foundation-Sec is linearly predictable from Llama's activation geometry at the same site.

The practical implication is that a single forward pass through the base model, followed by a linear projection, gives a per-script circuit-activity score for the fine-tuned model at low cost. For drift monitoring, the family-level average of this score under Llama versus Foundation-Sec reveals which capability families changed most in how strongly the inherited circuit is engaged after fine-tuning.

\paragraph{Indicator-token sign inversion as an evasion predictor.}
The linear probe's cross-model transfer is stronger at the family level, where per-script noise averages out. But activation magnitude alone does not predict which families will produce evasion misses. A more targeted signal comes from measuring how indicator-token ablation shifts the final classification output in each model separately. For each malicious script, we replace the indicator token embeddings with the vocabulary mean embedding and measure the resulting change in logit-diff.

For every family in Foundation-Sec, this ablation produces the expected negative delta — removing the indicator tokens reduces malicious confidence — \emph{except} \texttt{Invoke-WebRequest}. In that family, ablating the command-name tokens \emph{increases} average malicious confidence (\(+1.13\) mean logit-diff delta; 73.7\% of scripts show a positive delta). Llama shows the normal negative delta (\(-1.60\)) for the same family. This sign inversion is not observed in any other family.

The mechanistic interpretation is that fine-tuning caused Foundation-Sec to classify \texttt{Invoke-WebRequest} scripts through URL patterns, payload structure, and command arguments rather than through the command-name token itself. After training on enough legitimate \texttt{Invoke-WebRequest} admin scripts, the full command name acts as a mild suppressor at \texttt{resid\_pre13}: the model recognizes ``this could be benign'' from the token alone, while the surrounding payload context carries the actual malicious signal. When the alias \texttt{iwr} is substituted, the token-level suppression disappears along with the payload-context attention path it anchors, producing a miss.

The linear probe quantifies this through the indicator-token L2 sensitivity: the shift in \texttt{resid\_pre13} when indicator tokens are ablated is linearly predictable from the activation itself at \(r = 0.83\) (\(n = 293\), \(p < 10^{-75}\)), confirming that how strongly a script's representation depends on its indicator tokens is a linear property of \texttt{resid\_pre13}. The sign of the corresponding logit-diff delta — whether those tokens drive or suppress malicious classification — is the operative evasion predictor. A family where the fine-tuned model's ablation delta flips sign relative to the base model is specifically vulnerable to token-substitution attacks, and this flip is detectable on canonical clean inputs without generating any evasion variants in advance.

Operationally, this motivates the following monitoring recipe:
\begin{enumerate}[leftmargin=1.5em,itemsep=0.2em,topsep=0.2em,parsep=0pt]
  \item Fit a linear probe from base-model \texttt{resid\_pre13} activations to the head trace projections of the validated Layer-12 bundle.
  \item For each capability family, compare the mean projected head contribution under the base model versus the fine-tuned model on canonical clean inputs.
  \item For each family, ablate indicator tokens with mean embeddings in both models and compare the sign of the resulting logit-diff delta.
  \item Flag families where the ablation sign flips between base and fine-tuned model.
  \item Prioritize sign-flipped families for adversarial evaluation: generate alias and reconstruction variants within those families and test them against the fine-tuned model.
\end{enumerate}

This workflow requires only forward passes on canonical clean inputs — no evasion variants, no ablation experiments on the fine-tuned model, and no retraining. The sign inversion is directly and cheaply observable, and it correctly identifies the one family in this study that produced consistent evasion misses.

\section{Future Work}
Next steps for this line of work can include extending the validation cohort to cover additional indicator families beyond the seven reported here and to deeper per-family pair counts, so that the current 293-pair result can be stress-tested with a more independent validation design. On the robustness side, the evasion benchmark can expand along two fronts: deeper coverage inside the already active \texttt{keyword\_hiding}, \texttt{string\_construction}, and \texttt{execution\_indirection} families, and concrete tests for two currently theoretical families. \texttt{network\_object\_indirection} would hide direct networking surfaces behind equivalent object-construction, method-dispatch, or reflection patterns. \texttt{staged\_payload\_flow} would preserve the same malicious behavior while splitting retrieval, decoding, allocation, and execution across intermediate variables or helper functions.

On the mechanistic side, the main open question is which specific MLP components implement the replicated inversion effect after the validated Layer 12 bundle fires. The current evidence strongly supports grouped routes and residual-direction claims, and a concrete feed-forward inversion effect in the best-localized successful-evasion slice together with a second slice showing the same carrier-survival pattern, but it does not yet provide a full downstream decomposition of the competing write. Future work should therefore focus on identifying the specific MLP components that invert the decision signal before the Layer 13 boundary, especially in the successful-evasion setting, and on determining whether that MLP contribution is best understood as a distributed subnetwork, a feature-level representation, or a small number of still-unlocalized routes. The comparative result also motivates localizing Foundation-Sec's semantic weighting layer directly, especially the components that distinguish full-form \texttt{Invoke-Expression} and \texttt{Invoke-WebRequest} strings from aliases and reconstructed command names, and comparing the functional roles of \texttt{L12H15} and \texttt{L12H28} across the two models. The linear probe and indicator-token sign-inversion workflow should be validated on additional fine-tunes and capability families to assess how generally the sign-flip pattern predicts aliasing vulnerability.

\section{Conclusion}
This paper shows that applied mechanistic interpretability can produce a strong security-relevant circuit claim for malicious code classification rather than only a loose qualitative story. To our knowledge, this study is among the first mechanistic circuit analyzes in a cybersecurity LLM application context, combining causal circuit validation, cross-model comparison, and an evasion benchmark for malicious code classification. \citep{choi2020malicious,garciacarrasco2024detecting}

On the main 293-pair Foundation-Sec cohort, the validated route centered on \texttt{L0H11} and the Layer 12 late-stage bundle explains a substantial portion of the model's malicious decision signal: the minimal branch removes about \(77\%\) of the average malicious decision margin and flips \(87/293\) predictions, while the stronger late-stage bundle removes about \(81\%\) and also flips \(87/293\). The Llama comparison shows that this is not a completely new security-trained circuit. Llama shares the same \texttt{L0H11} early detector and Layer-12 integration stage, but uses a more diffuse late bundle centered on \texttt{L12H28}. On the matched 74-pair adversarial-prompt baseline, Foundation-Sec's remaining classification advantage is a \(4.7\)-point overall accuracy gain over Llama, driven entirely by a \(9.5\)-point improvement in benign accuracy rather than by improved malicious recall. In a cybersecurity setting, that is a substantial result: fine-tuning concentrates an inherited structural circuit and adds command-name semantic weighting rather than inventing the entire route.

The paper also contributes a concrete two-tier evasion benchmark constructed as matched seed/variant pairs. This pairing enables direct comparison between an original malicious script and its rewritten version. Any difference in internal circuit behavior between seed and variant can therefore be tied directly to the token-level transformation, rather than being mixed up with general classification difficulty. Across \(90\) accepted Foundation-Sec variants, Foundation-Sec stays correct on \(80\), and the misses are concentrated in three techniques: \texttt{Invoke-WebRequest} alias hiding, a narrower \texttt{FromBase64String}/\texttt{DownloadString} reconstruction slice, and the \texttt{reconstructive\_v2} failure mode \texttt{invoke\_expression\_format\_string}. In the controlled raw-prompt comparison, Llama has \(0/44\) misses on \texttt{direct\_v1} and \(0/46\) misses on \texttt{reconstructive\_v2}. This contrast supports the fine-tuning tradeoff: Foundation-Sec's semantic weighting improves raw-prompt security behavior, but also creates command-name brittleness. Just as importantly, the strongest Foundation-Sec successful-evasion results do not simply delete the validated malicious-evidence bundle. Instead, the evidence shows that later feed-forward computation can produce misclassification even when the circuit continues to carry a malicious signal earlier in the late stage.

Taken together, these results show that mechanistic interpretability can identify the internal circuitry responsible for security-relevant classification decisions, not merely summarize model behavior after the fact. Once such a mechanism is localized, it can be stress-tested directly: under matched examples, under cross-model comparison, and under syntax-preserving evasion. That makes circuit-level analysis useful both for evaluating models in critical applications and for guiding future model development. The comparative result also shows that security-relevant circuits can persist through fine-tuning, with Foundation-Sec inheriting the core PowerShell classification structure from Llama. At the same time, the evasion benchmark shows that fine-tuning can create a tradeoff: it improves the model for the intended classification task, but can also introduce new brittleness around the particular semantic features the fine-tuned model learns to rely on. This failure mode is best understood as semantic over-specialization rather than ordinary accuracy loss. A natural mitigation is to include behavior-preserving evasive variants during fine-tuning, paired with benign hard negatives and consistency objectives, so the model is rewarded for stable classification across aliases, reconstructed strings, and equivalent execution forms rather than for reliance on specific command literals. More practically, the same mechanistic localization yields a concrete activation-space monitoring workflow. A linear probe fit from base-model \texttt{resid\_pre13} activations to the validated Layer-12 head contributions encodes per-family circuit activity as a simple linear projection (\(r = 0.81\)--\(0.87\)), and transfers cross-model to Foundation-Sec at \(r = 0.41\). An indicator-token ablation experiment then reveals whether fine-tuning has inverted the role of specific command-name tokens: a sign flip in the ablation delta between base and fine-tuned model, detectable on canonical clean inputs without generating evasion variants, identifies the families most vulnerable to aliasing attacks and should be used to prioritize red-teaming targets after fine-tuning.
