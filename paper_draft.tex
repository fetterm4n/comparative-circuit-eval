\begin{abstract}
Security fine-tuning can make LLMs better at classifying malicious code on canonical inputs while also introducing evasion brittleness that standard accuracy evaluation does not detect. We demonstrate this concretely for PowerShell classification in Foundation-Sec-8B-Instruct. The cybersecurity fine-tune shows strong associations between specific full-form command names (\texttt{Invoke-WebRequest}, \texttt{Invoke-Expression}) and malicious classification. This improves accuracy on canonical inputs in our setting, but creates an attack surface invisible to held-out test sets: in the accepted variants tested here, replacing \texttt{Invoke-WebRequest} with its alias \texttt{iwr} — a trivial one-token substitution that preserves all malicious behavior — flips the model’s prediction. The base model it was fine-tuned from, Llama-3.1-8B-Instruct, has zero misses on the same substitutions. In this model pair, the fine-tuned model has vulnerabilities that were not present in the base model under the same evaluation.

We show this brittleness is predictable and detectable at the capability-family level before deployment in this model pair. Using causal interventions on a 293-pair matched cohort, we localize the classification circuit to a small set of late attention heads (Layer 12), and show this circuit is inherited from Llama rather than created by fine-tuning. A linear probe fit from base-model activations at the circuit boundary (\texttt{resid\_pre13}) to individual head contributions achieves \(r = 0.80\)--\(0.87\), confirming each head’s contribution is linearly encoded. An indicator-token ablation experiment then reveals the operative aliasing signal: in Foundation-Sec, ablating the \texttt{Invoke-WebRequest} command-name tokens \emph{increases} malicious confidence (\(+1.13\) mean delta, positive in 73.7\% of scripts), a clear divergence from Llama’s strong negative delta (\(-1.60\)) for the same family. This pattern — command name acting as suppressor in the fine-tuned model but as a driver in the base model — is detectable on canonical clean inputs without generating any evasion variants, and it identifies the family that later fails consistently under alias substitution. Prompt-level mitigations compound the problem: telling Foundation-Sec to ``classify based on overall purpose, not individual constructs’’ fixes the \texttt{Invoke-WebRequest} misses but simultaneously creates new misses on \texttt{Invoke-Expression} obfuscation. The semantic weighting introduced by fine-tuning is distributed across families in ways that interact non-trivially.

These results carry a direct operational implication for teams fine-tuning LLMs for security tasks: high accuracy on canonical test data does not imply robustness to aliasing attacks, and the observed brittleness is consistent with semantic reweighting induced by the fine-tuning distribution. Models trained on corpora where specific command names are correlated with maliciousness should therefore be treated as candidates for the same failure mode and tested explicitly.
\end{abstract}

\textbf{Keywords:} security fine-tuning, aliasing brittleness, evasion robustness, large language models, malware detection, PowerShell, causal intervention

\section{Introduction}
LLMs are increasingly deployed in security workflows — code triage, malware analysis, policy-based blocking — because they achieve strong accuracy on standard benchmarks. But high accuracy on canonical test data does not mean a model is robust to the kinds of input modifications that adversaries routinely apply. This paper investigates a specific and practically important failure mode: \emph{aliasing brittleness} introduced by security fine-tuning. A model fine-tuned to classify malicious PowerShell learns associations between specific command names and maliciousness. Those associations improve accuracy on canonical inputs, but they also create a class of attack — token substitution via aliases or runtime reconstruction — that was absent in the base-model comparison and is invisible to standard held-out evaluation.

The core finding is empirical and direct. Foundation-Sec-8B-Instruct, a cybersecurity fine-tune of Llama-3.1-8B-Instruct, achieves higher classification accuracy than its base model on the matched canonical PowerShell evaluation used here. But Foundation-Sec fails on specific functionality-preserving rewrites — replacing \texttt{Invoke-WebRequest} with \texttt{iwr}, or reconstructing \texttt{Invoke-Expression} via a format string — that preserve the malicious behavior. Llama, with no security fine-tuning, has \emph{zero misses} on the same substitutions under the same prompt framing. The fine-tuned model is therefore more accurate on the canonical slice but less robust on these rewritten variants.

This brittleness is not a random quirk. It follows directly from how fine-tuning changes the model's internal behavior. We show that Foundation-Sec learned to classify \texttt{Invoke-WebRequest} scripts primarily through URL patterns and payload context, with the full command-name token acting as a mild suppressor rather than a driver of malicious classification. The alias result is therefore a two-part failure: removing the full command name removes the suppressor, which by itself should increase malicious confidence, but the alias also disrupts the command-anchored payload-context path that carries the stronger malicious evidence. In the accepted \texttt{iwr} variants tested here, the second effect dominates and the prediction flips. This mechanism is detectable before deployment at the family level — on canonical clean inputs, no evasion variants required — using a simple indicator-token ablation test at the model's internal classification boundary.

We also show that prompt-level mitigations compound the problem in ways that are difficult to anticipate. Adding a prompt instruction to ``classify based on overall purpose, not individual constructs'' fixes the \texttt{Invoke-WebRequest} misses, but simultaneously opens new misses on \texttt{Invoke-Expression} obfuscation: the semantic weighting fine-tuning added is distributed across families and cannot be patched in one place without opening another. This makes the pre-deployment family-level red-teaming workflow more valuable than post-deployment prompt engineering.

The mechanistic analysis supporting these findings uses causal interventions on a 293-pair matched cohort — paired benign and malicious scripts sharing the same suspicious indicator strings, so that classification differences cannot be attributed to trivial surface features. We localize the classification decision to a small set of late-stage attention heads (Layer 12), show this circuit is inherited from Llama rather than created by fine-tuning, and use a linear probe and indicator-token ablation to establish both that the circuit information is linearly encoded at the classification boundary and that the sign of each family's token dependency predicts the observed family-level aliasing vulnerability in this benchmark.

The contributions of this paper are:
\begin{itemize}[leftmargin=1.5em,itemsep=0.15em,topsep=0.15em,parsep=0pt,partopsep=0pt]
  \item A demonstration that security fine-tuning can introduce aliasing brittleness invisible to standard accuracy evaluation, with Foundation-Sec producing misses on simple token substitutions that Llama handles correctly.
  \item A two-tier syntax-preserving evasion benchmark constructed from matched seed/variant pairs, enabling mechanistic attribution of classifier failures to specific token transformations.
  \item Evidence that the brittleness mechanism is a sign inversion: after fine-tuning, specific command-name tokens suppress rather than drive malicious classification, making their aliases evasion vectors in the tested slices.
  \item A pre-deployment red-teaming recipe: a linear probe at the model's classification boundary flags family-level representation drift, and an indicator-token sign test identifies families at risk of aliasing, without requiring evasion variant generation in advance.
  \item The finding that prompt-level mitigations for one brittle family can simultaneously open new brittleness in others, motivating data-level rather than prompt-level fixes.
\end{itemize}

\section{Prior Work}
Previous work on mechanistic interpretability provides the main template for this study. Early circuit work argued that neural networks can often be understood in terms of reusable features and the pathways that connect them \citep{cammarata2020thread}. Transformer-specific follow-up then formalized residual-stream communication and path-based decomposition \citep{elhage2021mathematical}, identified induction heads as a concrete algorithmic circuit for the completion of the in-context pattern \citep{olsson2022induction}, and showed that medium-scale language behavior can be partially decomposed into head-level circuits under causal intervention \citep{wang2023interpretability}. More recent work has also pushed toward more automated circuit discovery, which is directly relevant to the discovery-versus-validation split used here \citep{conmy2023automated}.

The model lineage matters for interpretation. Foundation-Sec-8B was introduced as a cybersecurity-focused derivative of the Llama 3.1 8B base architecture, obtained through continued pretraining on a curated cybersecurity corpus rather than training from scratch \citep{kassianik2025foundationsecbase}. Foundation-Sec-8B-Instruct then extends that base model with instruction tuning and human-preference alignment for chat-style cybersecurity use \citep{weerawardhena2025foundationsecinstruct}. This choice is relevant because the model was previously evaluated to perform favorably in PowerShell classification, with a reported \(+16\%\) precision gain over the baseline in a threat-hunting workflow  \citep{fetterman2025foundationsecpowershell}. It also creates a natural mechanistic control: if Foundation-Sec and Llama share the same circuit skeleton, then the cybersecurity fine-tuning should be interpreted as amplifying, reweighting, or adding semantic use of an inherited circuit rather than inventing a new one. Recent circuit analyses of fine-tuning similarly find that circuit nodes can remain highly similar before and after fine-tuning while the edge structure and functional weighting change \citep{wang2025finetuningcircuits}.

Adjacent robustness and security research motivate the evasion side of the paper. In malware detection and related security pipelines, detectors that perform well on nominal data can still fail under functionality-preserving adversarial modifications, and improving robustness often requires explicitly modeling the attack surface rather than assuming that high baseline accuracy implies stability \citep{lucas2023adversarial,mukherjee2023evading}. Our setting differs in that the detector is an LLM operating over PowerShell scripts, and the goal is mechanistic rather than purely behavioral. But the central concern is the same: if the model relies on brittle surface indicators, then conservative rewrites may change the decision without removing the underlying malicious behavior.

\section{Background}
This paper uses standard transformer notation. A label such as \texttt{L12H15} means \emph{Layer 12, Attention Head 15}. Attention heads read information from earlier tokens and write their output into a shared running state often called the \emph{residual stream}. When we say a head or layer ``carries malicious evidence,'' we mean that its contribution to this shared state pushes the model toward a malicious rather than benign classification. The model also contains \emph{MLP} blocks, the feed-forward sublayers that sit alongside attention in each transformer layer. In this paper, \texttt{resid\_pre13} simply names the shared activation state immediately before Layer 13.

We use the term \emph{circuit} in a narrow sense: a small set of model components whose activations causally matter for the classification decision under study. A \emph{route} is one specific path through that circuit. A \emph{late-stage bundle} is the group of late heads that transports the strongest malicious-versus-benign evidence near the output. A label such as \texttt{L0H11 $\rightarrow$ L12H15/L12H5/L12H4} should therefore be read as a shorthand summary of the route, not as the claim that these are the only relevant components in the full model.

Our main intervention tools are also simple in intent. \emph{Grouped path patching} asks whether copying activations from a malicious example into a candidate route is enough to recreate the malicious classification signal; in other words, it is primarily a sufficiency test. \emph{Grouped head ablation} asks whether removing a candidate group weakens the decision signal; it is primarily a necessity test. When we say a route is \emph{validated}, we mean that it survives these causal intervention checks on the matched cohort. When we say \emph{signal inversion}, we mean that the model still forms malicious evidence internally, but later computation changes the sign or use of that evidence before the final readout. Figures \ref{fig:route-comparison} and \ref{fig:shared-skeleton-reweighted-heads} provide the most direct visual summaries of these components and how they differ across the two models.

\section{Problem Setting}
The task is binary malicious-code classification for PowerShell scripts. The key mechanistic difficulty is that many suspicious strings are not uniquely malicious: benign administrative scripts can contain tokens such as \texttt{IEX}, \texttt{FromBase64String}, \texttt{DownloadString}, \texttt{Invoke-WebRequest}, or \texttt{-EncodedCommand}. We therefore use matched benign and malicious examples sharing suspicious indicators, so that the interpretability problem is not trivially solved by superficial token presence alone.

\section{Dataset and Evaluation Cohorts}
\subsection{Source Dataset}
The source corpus contains 2{,}556 labeled PowerShell scripts, derived from prior work\citep{FANG202130}. The class balance after filtering is approximately even. A substantial long tail of long scripts motivated  a 12,000-character pre-processing cap when building the analysis manifests and construction of the matched cohorts, so benign and malicious scripts were paired and selected under explicit length control rather than letting the very longest scripts dominate the mechanistic runs. The main evidentiary basis for this draft is a 293-pair within-family matched cohort drawn from 456 unique scripts across the seven indicator families, in which benign and malicious scripts share suspicious indicators while remaining length-controlled enough for the intervention pipeline. This cohort was filtered from 380 candidate pairs by requiring both members of each pair to be correctly classified at baseline. 

\section{Methods}
\subsection{Discovery}
The goal of the discovery phase is to identify a small number of candidate components that repeatedly carry malicious-versus-benign evidence before we run the stronger causal tests in the validated route analysis below. Concretely, we first inspect \emph{attention recurrence}: whether the same early and late heads repeatedly attend to suspicious command spans, URLs, or execution sites across matched examples. We then use reduced-layer head interventions and coarse full-model layer ablation to ask a localization question: if a candidate head or layer band is removed, does the malicious judgment weaken enough to justify carrying that component forward into the validated route search? This is methodologically closest to earlier circuit-discovery work that treats attention patterns, residual-stream communication, and coarse intervention effects as a way to narrow the search space before making a sharper causal claim \citep{cammarata2020thread,elhage2021mathematical,conmy2023automated,ameisen2025attributiongraphs}.

Two discovery tools are especially important for the present paper. First, \emph{residual-direction patching} defines a task-aligned direction from matched benign-versus-malicious examples and then asks whether replacing activations at a given site moves the model along that malicious direction. Intuitively, this tests whether a location in the network is carrying classification-relevant evidence rather than only showing generic activation magnitude. Second, \emph{head-write tracing} breaks the contribution at that site into the individual head outputs that push in that direction, which lets us identify a small set of dominant heads instead of treating an entire layer as monolithic. These discovery analyses do not by themselves establish a validated circuit, but they are the reason the final claim can be stated narrowly as an \texttt{L0H11}-to-Layer-12 route rather than as a vague statement about ``early'' and ``late'' computation. This use of residual directions, head-level intervention, and candidate-route narrowing follows the general logic of recent transformer-circuit studies, especially work on induction-style circuits, IOI-style causal localization, and automated circuit search \citep{olsson2022induction,wang2023interpretability,conmy2023automated}.

\subsection{Validation}
The final claim is based on grouped interventions on the 293-pair cohort:
\begin{itemize}[leftmargin=1.5em,itemsep=0.2em,topsep=0pt,parsep=0pt,partopsep=0pt]
  \item \textbf{Grouped path patching} is used primarily as a sufficiency test.
  \item \textbf{Grouped head ablation} is used primarily as a necessity test.
\end{itemize}

In simple terms, a \emph{sufficiency} test asks whether a candidate route is enough to recreate the relevant behavior when its activations are patched in from a malicious example. A \emph{necessity} test asks whether the behavior weakens when that route is removed or disabled. These are related but not identical questions: a route can be sufficient without being strictly necessary if the model has backup pathways, and it can be necessary in a narrow setting without being the cleanest transportable route for patching.

Throughout the paper, \emph{mean intervention effect} refers to the average shift produced by an intervention on the model's malicious-versus-benign decision score, measured as the post-intervention score minus the original score. A more negative mean effect therefore indicates that the intervention weakens the malicious judgment; for patching and ablation experiments that remove or corrupt the route, larger negative values indicate stronger causal dependence on the removed route. \emph{Flip rate} reports how often that intervention is strong enough to change the model's final predicted label.

\subsection{Evasion}
We evaluate syntax-preserving obfuscation techniques and then, for the strongest misses, compare each original malicious script with its rewritten variant using the same circuit probes. Candidate variants are generated only from malicious seed scripts that the model initially classifies correctly, so the evasion benchmark measures failures relative to seeds that already pass the baseline classifier. Throughout this section, \texttt{evasion} means behavioral evasion of classification, that is, a malicious variant that the model now predicts benign. The central mechanistic question is whether successful evasion removes the validated malicious-evidence route or instead preserves that route while later computation changes how that evidence is used. In the best-localized current case, this change appears at the Layer 13 boundary: feed-forward computation before that boundary introduces a competing signal that reverses the effect of the surviving late-stage bundle.

The implemented benchmark is two-tiered. \texttt{direct\_v1} relies on alias substitution, call-operator indirection, token splitting, and literal or method-name reconstruction. \texttt{reconstructive\_v2} stresses the classifier with character-level and command-reconstruction patterns that are often seen in obfuscated PowerShell, including backticks, format strings, ASCII or Base64 recovery, invisible Unicode normalization, and alternate quoting or subexpressions. The benchmark schema defines five broad evasion families; this draft instantiates the \texttt{keyword\_hiding}, \texttt{string\_construction}, and \texttt{execution\_indirection} families.

The implemented benchmark pipeline is more specific than a generic ``obfuscation sweep.'' It first builds a malicious seed manifest restricted to baseline-correct malicious scripts. It then applies only a fixed set of allowed rewrites from the requested preset (\texttt{direct\_v1} or \texttt{reconstructive\_v2}), and each rewrite is used only on scripts where it makes sense. For example, a rewrite that hides \texttt{Invoke-WebRequest} is only applied to seeds that actually contain that command, and a rewrite intended for cross-runtime PowerShell is only used when the target script fits that runtime setting. Each generated variant is then reviewed with static parsing, using the PowerShell parser when the required runtime is available and a \texttt{tree-sitter} fallback otherwise, together with explicit invariant checks to ensure underlying behavior is not changed. The current invariant checks require preservation of URL sets, executable or path-like literals, and \texttt{-EncodedCommand} equivalence where relevant, and they also enforce technique-specific argument-preservation checks such as preserved request arguments or preserved process-launch arguments. The malicious seed / variant pairing is what makes the mechanistic experiments interpretable, we measure the same circuit on the same script content under two conditions (literal token present vs. absent) and attribute any difference in the residual stream directly to the token transformation.

\section{Evaluation \& Results}
\subsection{Results at a Glance}
\begin{itemize}[leftmargin=1.5em,itemsep=0.2em,topsep=0pt,parsep=0pt,partopsep=0pt]
  \item \textbf{Fine-tuning is associated with evasion brittleness absent from the base-model comparison:} Foundation-Sec produces \(6/44\) misses on direct alias substitution and \(4/46\) misses on command reconstruction. Llama has \(0/44\) and \(0/46\) misses on the same variants under the same prompt framing. These failures are specific to the fine-tuned model in this controlled model-pair comparison.
  \item \textbf{Brittleness is family-specific, not uniform:} Failures concentrate in \texttt{Invoke-WebRequest} alias substitution (\(4/4\) misses) and \texttt{Invoke-Expression} format-string reconstruction (\(4/4\) misses). Other tested command families are robust under the accepted variants in the implemented benchmark, but the strongest positive slices are small and should be expanded before treating the rates as population estimates.
  \item \textbf{Sign inversion predicts the vulnerable family at the right granularity:} Ablating \texttt{Invoke-WebRequest} tokens from Foundation-Sec \emph{increases} malicious confidence (\(+1.13\) mean delta; positive in 73.7\% of scripts); the same ablation \emph{reduces} Llama's confidence (\(-1.60\)). This family-level sign flip — observable on canonical inputs without generating any evasion variants — identifies the family that produces consistent misses in the current benchmark and should be treated as the primary pre-deployment red-teaming signal.
  \item \textbf{Prompt-level mitigations trade one weakness for another:} Instructing Foundation-Sec to classify based on overall purpose rather than individual constructs fixes the \texttt{Invoke-WebRequest} misses but simultaneously opens new misses on \texttt{Invoke-Expression} obfuscation. The semantic weighting introduced by fine-tuning is distributed across families and cannot be patched in one place without opening another.
  \item \textbf{The classification circuit is inherited from Llama, not created by fine-tuning:} Causal interventions on 293 matched script pairs confirm that Foundation-Sec relies on a small late-stage attention bundle (Layer 12) that Llama also uses. Fine-tuning concentrated and semantically specialized this existing mechanism; it did not invent it. This matters because the circuit's vulnerability profile appears to reflect both the base model's structure and semantic weighting introduced during fine-tuning.
  \item \textbf{Activation-space monitoring is practical and cheap at family level:} A linear probe from base-model activations at the circuit boundary predicts each head's contribution at \(r = 0.80\)--\(0.87\). Cross-model transfer to Foundation-Sec ablation dependence reaches \(r = 0.41\), making per-script prioritization noisy but supporting family-level red-teaming when averaged across canonical examples.
\end{itemize}

\subsection{Circuit Results}
\subsubsection{Validated Late Route}
On the 293-pair cohort, causal patching supports a minimal direct branch:
\[
\texttt{L0H11} \rightarrow \texttt{L12H15/L12H5/L12H4}
\]
The mean patching effect is approximately \(-3.614\), which means that the intervention reduces the model's average malicious-versus-benign decision margin from about \(4.71\) to about \(1.10\). In other words, it removes roughly \(77\%\) of the average malicious decision margin and flips the final prediction on \(87/293\) pairs (\(0.297\)).

The stronger late-stage bundle is:
\[
\texttt{L12H15/L12H5/L12H4/L12H28}
\]
Its mean patching effect is approximately \(-3.824\), which reduces the same average malicious-versus-benign decision margin from about \(4.71\) to about \(0.89\). In other words, it removes roughly \(81\%\) of the average malicious decision margin and also flips the final prediction on \(87/293\) pairs (\(0.297\)).

The role of \texttt{L12H2} is more nuanced. Removing \texttt{H2} improves the main path-patching result, while the full top-five bundle remains slightly stronger under grouped ablation. Our current interpretation is therefore that \texttt{L12H2} is an auxiliary family-sensitive helper, not part of the most stable sufficiency core.

\subsubsection{Interpretation of Early and Late Stages}
The results support an early Layer 0 detector family, especially \texttt{L0H11} and \texttt{L0H9}. However, the final validated claim in this draft does not rest on a broad early-head story. Instead, it uses \texttt{L0H11} as the clearest entry point into the validated late route. The stronger late-stage evidence localizes to attention around Layers 12--13 and to feed-forward computation before the Layer 13 boundary that becomes especially important in the successful-evasion setting.

\subsubsection{Family-Level Variation}
The 293-pair cohort also reveals a useful family-level pattern. The best patch route is not identical across all indicator families. The minimal branch is strongest for \texttt{DownloadFile}, the fuller top-five late bundle is strongest for \texttt{DownloadString} and \texttt{IEX}, and the \texttt{H2}-free carrier (late Layer-12 head bundle with L12H2 removed) is strongest for \texttt{-EncodedCommand}, \texttt{Invoke-Expression}, and \texttt{Invoke-WebRequest}. This pattern supports the current interpretation that \texttt{H2} is not part of the most stable sufficiency core. One caveat: the \texttt{-EncodedCommand} family (7 pairs) shows zero flip rate under all patching variants, indicating that the circuit claim is weakest for this family and that it warrants a cautionary note; the other six families show consistent negative mean deltas across all route variants.

At the same time, grouped ablation suggests that \texttt{H2} still contributes a necessity signal across most families: the top-5 bundle (mean \(\Delta = -2.174\)) is stronger than the H2-free carrier (mean \(\Delta = -1.893\)), confirming \texttt{H2} as an auxiliary helper that matters for necessity even while it weakens patching sufficiency. The family-level picture therefore reinforces the write-up distinction between a stable late-stage bundle and a narrower auxiliary helper.

This comparison changes the interpretation of the Foundation-Sec results. The cleanest account is not that security training created the \texttt{L0H11}-to-Layer-12 circuit. Instead, fine-tuning appears to concentrate causal weight into a smaller late-head set and add semantic associations between full-form PowerShell command names and the final \texttt{BLOCK} decision. This is consistent with fine-tuning work showing node-level circuit persistence alongside edge and weighting changes \citep{wang2025finetuningcircuits}. On the matched 74-pair adversarial-prompt baseline, that semantic weighting corresponds to a \(4.7\)-percentage-point overall accuracy gain over Llama (\(100\%\) vs.\ \(95.3\%\)), driven entirely by a \(9.5\)-point benign-accuracy improvement (\(100\%\) vs.\ \(90.5\%\)) rather than by improved malicious recall. Notably, fine-tuning does not straightforwardly strengthen the circuit's causal margins: Llama's late carrier mean patching effect is \(-5.45\) versus Foundation-Sec's \(-3.82\) on a comparable route, and Llama's mean base logit diff for malicious examples is \(8.15\) versus Foundation-Sec's \(3.75\). This suggests that fine-tuning concentrates and semantically specialises the circuit without increasing its absolute signal strength, and indeed may attenuate the base model's stronger discriminative representation. The current evidence therefore supports a mechanistic story in which fine-tuning preserves an inherited structural route but adds semantic weighting that can invert the malicious-evidence signal before final readout. That semantic layer is useful for raw-prompt operation, but the evasion benchmark below shows that it also creates a specific attack surface around aliases and command reconstruction.

\subsection{Evasion Results}
Foundation-Sec's results separate cleanly by tier. Because the benchmark is conditioned on baseline-correct malicious seeds, these evasion failures should be read as misses on scripts the model initially handled correctly before rewriting. In \texttt{direct\_v1}, Foundation-Sec stays correct on \(38/44\) accepted variants and the misses are concentrated in two techniques rather than spread broadly across the conservative benchmark. The strongest direct-tier failure remains simple alias substitution in the \texttt{Invoke-WebRequest} family: replacing the full command name with \texttt{iwr} yields misses on all four accepted variants tested. The only other positive result in that tier is narrower. Indirect \texttt{DownloadString} method invocation produces misses in two of six variants, and both of those misses come from \texttt{FromBase64String}-linked seeds rather than from the direct \texttt{DownloadString} seeds themselves.

Foundation-Sec classification accuracy is still strong under the second tier. In \texttt{reconstructive\_v2}, it stays correct on \(42/46\) candidates. All four misses come from one keyword-hiding technique, \texttt{invoke\_expression\_format\_string}. The other reconstructive rewrites---including backtick splitting, Base64 or ASCII reconstruction, subexpression strings, and zero-width normalization for \texttt{-EncodedCommand}---remain negative in the current run. Across both implemented tiers together, Foundation-Sec stays correct on \(80/90\) accepted variants, so the observed weaknesses are specific and technique-concentrated rather than benchmark-wide. Because the positive slices are small, these results should be read as localized counterexamples and red-teaming priorities, not as stable estimates of real-world evasion prevalence.

The strongest mechanistic result on a Foundation-Sec successful-evasion slice is not that the validated route disappears. Instead, under \texttt{invoke\_webrequest\_alias}, the usual late malicious-evidence bundle remains visible earlier in the late stage: the validated late bundle still fires on the miss variants, but later feed-forward computation before the Layer 13 boundary reverses the direction that reaches later computation. In that slice, the failure is therefore better described as later computation reversing surviving evidence than as route deletion. The \texttt{reconstructive\_v2} miss slice provides an independent replication of the same carrier-survival story, though not yet the same degree of localization for the competing write. On \texttt{invoke\_expression\_format\_string}, early-head ablation still flips \(4/4\) variants, the minimal direct patch route still flips \(4/4\) with mean effect about \(-0.875\), and the fuller late bundle still flips \(4/4\) with mean effect about \(-1.03\), even though removing that late bundle pushes the model in the opposite direction on the evaded variants. In the current interpretation, both slices are therefore better explained by preserved late-bundle activity plus an inversion-producing competing write than by simple route deletion. This framing is consistent with the broader lesson from recent mechanistic studies that behaviorally similar outputs can arise from materially different internal pathways and downstream uses of shared evidence \citep{lindsey2025biology}.

The current evidence does \emph{not} support a generic statement that direct or reconstructive obfuscation automatically defeats these models. In Foundation-Sec \texttt{direct\_v1}, misses occur only in \texttt{invoke\_webrequest\_alias} and the narrower \texttt{downloadstring\_psobject\_invoke} pattern concentrated in \texttt{FromBase64String}-linked seeds. In Foundation-Sec \texttt{reconstructive\_v2}, misses occur only in \texttt{invoke\_expression\_format\_string}; the other tested backtick, Base64 or ASCII, subexpression, and zero-width-normalization techniques remain robust among the accepted variants in the current run. Llama's controlled raw-prompt results, \(0/44\) misses on \texttt{direct\_v1} and \(0/46\) misses on \texttt{reconstructive\_v2}, show that the same architectural circuit can be less brittle when it remains more diffuse and less tied to Foundation-Sec's full-form command-name semantics.

\subsection{Monitoring Fine-Tuning Drift}
The comparative and evasion results support a practical operational extension. Foundation-Sec inherits the underlying PowerShell classification route from Llama, but its failures after fine-tuning are not best explained as deletion of that inherited mechanism. Instead, the current evidence points to a narrower change in how later computation uses that inherited signal: the relevant malicious-evidence representation still appears at the causally important \texttt{resid\_pre13} site, while downstream computation can suppress, redirect, or invert its effect for particular semantic families. This makes \texttt{resid\_pre13} a useful monitoring anchor for family-level regression testing after security fine-tuning.

\paragraph{Linear probe at the circuit boundary.}
We fit a linear probe (Ridge regression, 5-fold cross-validation) from the \texttt{resid\_pre13} activation of each malicious script to the per-head contribution of the four core Layer-12 heads measured by the head trace experiment. The probe achieves cross-validated \(r = 0.80\)--\(0.87\) for \texttt{L12H4}, \texttt{L12H5}, \texttt{L12H15}, and \texttt{L12H28} (\(n = 206\), all \(p < 10^{-45}\)). These values confirm that each head's contribution to the contrastive direction is \emph{linearly} encoded in \texttt{resid\_pre13} — meaning the information is directly readable as a simple linear projection of the inherited representation, not just extractable by a more flexible model.

Operationally, this gives a cheap drift quantity: run one forward pass through Llama and one through Foundation-Sec on canonical clean inputs, apply the same learned linear projection to each model's \texttt{resid\_pre13} activations, and compare the projected head contribution by capability family. If Foundation-Sec has preserved the inherited representation for a family, the family mean should remain close to the Llama mean. If fine-tuning compresses, rotates, or inverts that family's representation at the circuit boundary, the projected contribution will diverge. Applied cross-model at the script level, the same probe predicts Foundation-Sec's causal circuit dependence (\texttt{delta\_logit\_diff} under top-5 L12 ablation) at \(r = 0.41\) (\(n = 293\), \(p < 10^{-12}\)). This is useful but also sets the ceiling: per-script prioritization is noisy, so the intended operational unit is a family-level red-teaming priority, where averaging over scripts stabilizes the signal.

The practical implication is not that the probe reliably ranks individual scripts by future evasion risk. Rather, the family-level average of the projected contribution under Llama versus Foundation-Sec reveals which capability families changed most in how strongly the inherited circuit is represented after fine-tuning. Those families are the natural first targets for adversarial variant generation.

\paragraph{Indicator-token sign inversion as an aliasing signal.}
The linear probe's cross-model transfer is strongest at the family level, where per-script noise averages out. But projection magnitude alone does not determine which changed families are specifically vulnerable to aliasing. A sharper signal comes from measuring how indicator-token ablation shifts the final classification output in each model separately. For each malicious script, we replace the indicator token embeddings with the vocabulary mean embedding and measure the resulting change in logit-diff.

Most families in Foundation-Sec show the expected pattern: removing the indicator tokens reduces malicious confidence, consistent with those tokens acting as drivers of the malicious prediction. \texttt{Invoke-WebRequest} is the clear exception. Ablating its command-name tokens \emph{increases} average malicious confidence (\(+1.13\) mean logit-diff delta; 73.7\% of scripts show a positive delta), while Llama shows a strong negative delta (\(-1.60\)) for the same family. The divergence between the two models is most pronounced here: all other families stay within a narrow band, while \texttt{Invoke-WebRequest} is the only family with a large positive FS delta alongside a clearly negative Llama delta. Figure~\ref{fig:ablation-delta} shows the full family-level comparison.

\caption{Mean logit-diff delta when indicator tokens are mean-ablated, broken down by indicator family and model. The mechanistic interpretation is that fine-tuning appears to have led Foundation-Sec to classify \texttt{Invoke-WebRequest} scripts through URL patterns, payload structure, and command arguments rather than through the command-name token itself. The evidence separates two effects. On canonical inputs, mean-ablating the full command-name token increases malicious confidence, so the token itself behaves like a suppressor. On the successful \texttt{iwr} variants, however, the validated late bundle still appears while later computation changes the downstream use of that evidence, indicating that the alias transformation also disrupts or reroutes the command-anchored payload-context signal. The miss therefore does not follow from suppressor removal alone; it follows from suppressor removal plus loss or inversion of the stronger contextual evidence path, with the latter dominating in the accepted variants tested here.

The linear probe quantifies the representation side of this effect through indicator-token L2 sensitivity: the shift in \texttt{resid\_pre13} when indicator tokens are ablated is linearly predictable from the activation itself at \(r = 0.83\) (\(n = 293\), \(p < 10^{-75}\)), confirming that how strongly a script's representation depends on its indicator tokens is a linear property of \texttt{resid\_pre13}. The sign of the corresponding logit-diff delta — whether those tokens drive or suppress malicious classification — is the operative aliasing signal in this benchmark. A family where the fine-tuned model's ablation delta flips sign relative to the base model should be prioritized for token-substitution attacks, and this flip is detectable on canonical clean inputs without generating any evasion variants in advance.

Operationally, this motivates a two-stage family-level monitoring recipe:
\begin{enumerate}[leftmargin=1.5em,itemsep=0.2em,topsep=0.2em,parsep=0pt]
  \item \textbf{Family-level representation drift screen:} fit a linear probe from Llama \texttt{resid\_pre13} activations to the measured head-trace projections of the validated Layer-12 bundle.
  \item Apply that same projection to Llama and Foundation-Sec \texttt{resid\_pre13} activations on canonical clean inputs.
  \item Aggregate projected head contribution by capability family and flag families with large Foundation-Sec-vs-Llama drops or sign changes.
  \item \textbf{Targeted indicator-token sign test:} ablate indicator tokens with mean embeddings in both models and compare the sign of the resulting logit-diff delta.
  \item Prioritize sign-flipped or strongly drifted families for adversarial evaluation: generate alias and reconstruction variants within those families and test them against the fine-tuned model.
\end{enumerate}

The first-stage screen requires only one forward pass per model on canonical clean inputs plus one linear projection; it requires no evasion variants, ablations, or retraining. The second-stage sign test does require indicator-token ablations on the base and fine-tuned models, but still uses only canonical clean inputs rather than generated evasions. The sign inversion is directly observable and correctly identifies the one family in this study that produced consistent alias-substitution misses.

\section{Limitations}
The main limitation is scope. The mechanistic and evasion claims are based on one fine-tuned model, its Llama base model, and one PowerShell classification setting. The cross-model comparison is therefore a strong control for this model pair, but it does not by itself establish that all security fine-tunes will develop the same brittleness. The evasion benchmark also contains small positive slices: the strongest failures are \(4/4\) accepted \texttt{Invoke-WebRequest} alias variants and \(4/4\) accepted \texttt{Invoke-Expression} format-string variants. These are important counterexamples, but they should be treated as red-teaming signals rather than population-level evasion-rate estimates until replicated with larger per-family coverage.

The matched cohort is filtered to examples that both members of each pair handle correctly at baseline, which is useful for causal interpretation but narrows the evaluated distribution. The activation-space monitoring result is also strongest at the family level: cross-model transfer to Foundation-Sec ablation dependence reaches \(r = 0.41\), so individual-script prioritization should be treated as noisy rather than deployment-ready. The current analysis also does not fully localize the downstream MLP components that appear to invert or reroute the late-stage evidence before the Layer 13 boundary. Finally, the draft argues that the observed brittleness is consistent with semantic weighting introduced by fine-tuning, but it does not directly measure the fine-tuning corpus statistics that would be needed to prove a specific data-distribution cause.

\section{Future Work}
Next steps for this line of work can include extending the validation cohort to cover additional indicator families beyond the seven reported here and to deeper per-family pair counts, so that the current 293-pair result can be stress-tested with a more independent validation design. On the robustness side, the evasion benchmark can expand along two fronts: deeper coverage inside the already active \texttt{keyword\_hiding}, \texttt{string\_construction}, and \texttt{execution\_indirection} families, and concrete tests for two currently theoretical families. \texttt{network\_object\_indirection} would hide direct networking surfaces behind equivalent object-construction, method-dispatch, or reflection patterns. \texttt{staged\_payload\_flow} would preserve the same malicious behavior while splitting retrieval, decoding, allocation, and execution across intermediate variables or helper functions.

On the mechanistic side, the main open question is which specific MLP components implement the replicated inversion effect after the validated Layer 12 bundle fires. The current evidence strongly supports grouped routes and residual-direction claims, and a concrete feed-forward inversion effect in the best-localized successful-evasion slice together with a second slice showing the same carrier-survival pattern, but it does not yet provide a full downstream decomposition of the competing write. Future work should therefore focus on identifying the specific MLP components that invert the decision signal before the Layer 13 boundary, especially in the successful-evasion setting, and on determining whether that MLP contribution is best understood as a distributed subnetwork, a feature-level representation, or a small number of still-unlocalized routes. The comparative result also motivates localizing Foundation-Sec's semantic weighting layer directly, especially the components that distinguish full-form \texttt{Invoke-Expression} and \texttt{Invoke-WebRequest} strings from aliases and reconstructed command names, and comparing the functional roles of \texttt{L12H15} and \texttt{L12H28} across the two models. The linear probe and indicator-token sign-inversion workflow should be validated on additional fine-tunes and capability families to assess how generally family-level projection drift and sign flips predict aliasing vulnerability.

\section{Conclusion}
This paper shows that applied mechanistic interpretability can produce a security-relevant circuit claim for malicious code classification rather than only a qualitative account of model behavior. To our knowledge, this study is among the first mechanistic circuit analyses in a cybersecurity LLM application context, combining causal circuit validation, cross-model comparison, and a matched seed/variant evasion benchmark for PowerShell classification \citep{choi2020malicious,garciacarrasco2024detecting}.

On the main 293-pair Foundation-Sec cohort, interventions centered on \texttt{L0H11} and a Layer 12 late-stage bundle remove about \(77\%\)--\(81\%\) of the average malicious decision margin and flip \(87/293\) predictions. The Llama comparison shows that this route is inherited rather than newly created: both models use the same early detector and Layer-12 integration stage, while Foundation-Sec concentrates weight into a more specialized late-head bundle and adds command-name semantic weighting.

That semantic weighting creates a measurable robustness tradeoff in this model pair. Across \(90\) accepted Foundation-Sec evasion variants, the model stays correct on \(80\), but its misses concentrate in \texttt{Invoke-WebRequest} alias hiding, a narrower \texttt{FromBase64String}/\texttt{DownloadString} reconstruction slice, and \texttt{invoke\_expression\_format\_string}. Llama has \(0/44\) misses on \texttt{direct\_v1} and \(0/46\) misses on \texttt{reconstructive\_v2} under the same raw-prompt framing. The strongest Foundation-Sec misses do not simply delete the validated malicious-evidence bundle; they preserve late evidence while later computation changes how that evidence is used.

The practical result is a pre-deployment family-level monitoring workflow. A linear probe fit from base-model \texttt{resid\_pre13} activations to the validated Layer-12 head contributions captures circuit activity as a simple projection (\(r = 0.80\)--\(0.87\)). Comparing that projection across Llama and Foundation-Sec on canonical inputs identifies families whose inherited representation changed after fine-tuning. A targeted indicator-token ablation then reveals whether fine-tuning has inverted the role of specific command-name tokens. In this study, the sign flip for \texttt{Invoke-WebRequest} identifies the family that later fails under alias substitution, making it a concrete red-teaming priority after security fine-tuning. The cross-model transfer value of \(r = 0.41\) sets the appropriate scope: this is a family-level red-teaming signal, not a reliable per-script evasion predictor.
